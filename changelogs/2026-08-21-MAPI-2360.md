## What Changed

- Webhook create (`POST /v1/webhooks/messages`) and update (`PATCH /v1/webhooks/messages/{webhookId}`) now document URL validation rules: `http`/`https` scheme, RFC 1123 hostname syntax, and paths free of whitespace or control characters; invalid URLs return HTTP 400.
- The 400 error response schema and examples now include a `details` array (e.g. `/url: Not a valid http url`, `/events/0: [RECEIVED_123] is invalid`, `Failed to parse message body.`).
- Generated API reference pages for Create webhook and Update webhook were refreshed to match the updated spec.

## Why

The `rest-api-webhooks` service now rejects malformed webhook URLs at the API boundary; the developer docs and OpenAPI spec needed to reflect that behaviour and the actual 400 response shape.

## Affected Components

- `spec` (webhooks schemas and paths)
- `docs/api/webhooks-management`
