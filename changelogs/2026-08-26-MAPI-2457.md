## What Changed

- Document that optional per-message `callback_url` on `POST /v1/messages` must use `http`/`https`, an RFC 1123 hostname, and a path without whitespace or control characters; malformed values return HTTP 400.
- Clarify that one invalid `callback_url` in a multi-message request rejects the entire batch.
- Add an HTTP 400 example with `/messages/0/callbackUrl: Invalid callback url`.

## Why

The Messages API now rejects malformed per-message callback URLs at send time; public developer docs and the OpenAPI spec needed to match that behaviour so customers can fix integrations before deployment.

- `spec` (Message schema and send-messages path)
- `docs/api/messages`
