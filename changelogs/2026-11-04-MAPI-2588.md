## What Changed

- Public Messages docs and OpenAPI now describe `rich_content.card` (`title`, `description`, `height`, `media`, up to 4 nested suggestions) as an alternative to `content` or `rich_content.media` for `format: "RCS"`, with request and GET-status examples and optional SMS `fallback_message`.
- Docs state that card `media` uses the same shape as standalone `rich_content.media`, that nested suggestions reuse the existing suggestion types, and that `calendar` is not supported.
- Docs list the `400` cases for cards: combined with `content`, top-level `suggestions`, or sibling `media`; empty / height-only / suggestions-only cards; more than 4 suggestions; invalid media URLs; unknown media fields.
- Empty `rich_content` wording is updated to `rich_content must include media or card`.
- Shared OpenAPI schemas extract `RcsRichMedia` and `RcsSuggestion` for reuse by media, cards, and top-level suggestions.
- `llms` curation mentions rich cards.

## Why

RCS rich cards on `/v1/messages` (epic MAPI-2367) are available to RCS-enabled accounts, and customers need the contract in the developer portal to use them.
