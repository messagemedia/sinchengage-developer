## What Changed

- Public Messages docs and OpenAPI now describe `rich_content.location` (required nested `coordinates` and `title`, optional `label` up to 1000 characters) as an alternative to `content`, `rich_content.media`, or `rich_content.card` for `format: "RCS"`, with request and GET-status examples and optional SMS `fallback_message`.
- Docs distinguish a standalone location pin from a tappable `location` suggestion, and document latitude `[-90, 90]` / longitude `[-180, 180]` bounds for both `rich_content.location` and location suggestions via a shared `RcsCoordinates` schema.
- Docs list the `400` cases for location pins: combined with `content`, top-level `suggestions`, or sibling rich pieces; missing coordinates/title; out-of-range coordinates; overlong `label`.
- Empty / exclusive `rich_content` wording is updated to match the API (`media, card, carousel or location`).
- `llms` curation mentions RCS location pins.

## Why

Standalone RCS location pins on `/v1/messages` (epic MAPI-2367) are available to RCS-enabled accounts, and customers need the contract in the developer portal to use them.
